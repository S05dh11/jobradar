## 二、协议契约

### SSE 事件(`text/event-stream`,与 /api/radar 同帧格式 `data: {json}\n\n`)

- `{type:"stage", stage:"analyzing"|"done"}` — 阶段推进
- `{type:"search", query, count}` — 判断轮真实补搜一次(前端计数只认这个事件)
- `{type:"retry", stage:"extract"|"conclusion", attempt}` — 发生了自动重试(段 1 重试在开流前,开流后补放一条事件,保证过程可观测)
- `{type:"done", report}` — 最终报告
- `{type:"error", message}` — 流内失败(含模型原文片段)

### done.report(外层五键保持不变,向后兼容)

```jsonc
{
  "extracted": { "skills": [], "education": null, "years": null, "projects": [], "degreeYear": null, "intent": null },
  "hit":   [{ "skill": "", "rank": 1, "evidence": "market_pool", "url": "?" }],
  "gaps":  [{ "skill": "", "rank": 2, "evidence": "search", "url": "?" }],
  "target": { "category": "", "city": "", "reason": "", "evidence": "market_pool", "url": "?" },
  "conclusion": "",
  "searches": [{ "query": "", "url": "?" }],   // 实际发生的补搜;空数组=岗位池证据足够,本身是有效结果
  "stages": { "extractMs": 0, "agentMs": 0 }
}
```

`evidence` 枚举:`resume`(简历照片) / `market_pool`(本次岗位池) / `search`(判断轮补搜)。`rank` 为岗位池技能词频名次(复用 `agent.ts` 的 `buildSkillRanking`),非词频依据不写。

## 三、关键设计决策及理由

1. **段 1 排在开 SSE 流之前**。任务书要求段 1 双失败返回 502(沿用旧行为),而 SSE 一旦发出头帧 HTTP 状态就锁定 200,无法两全。取舍:段 1(视觉提取,不涉及需要直播的过程)在返回 Response 前完成,失败是真 502 + JSON `{error}` 且保留模型原文片段;段 3 失败发生在流内,只能以 error 事件承载(消息同样带原文片段),前端按失败态展示。前端在等待开流期间本地显示「提取简历中」,真实不虚报。

2. **重试策略(按拍板修订,优于任务书原案)**:
   - 段 1 JSON 解析/结构失败 → 视觉整体重试 1 次。重试发生在任何搜索之前,零配额损耗;双失败才 502。
   - 段 3 JSON 解析/结构失败 → **保留段 2 完整对话**(system/user/全部 tool 往返都在),追加一条 user 纠错消息后**不带工具**重问 1 次。`ark.ts` 在 `tools=[]` 时从请求体省略 `tools`/`tool_choice`,模型在协议层就无法再发起搜索,`searches` 保持单次运行真实值。原任务书的「整体重试」在段 3 最坏会翻倍烧 6 次搜索,本方案消除该风险。

3. **判断轮循环仿 `agent.ts` 骨架**(系统提示词【纪律】段落式、TOOL_DEFS、预算回传、工具失败软降级为 tool 文本),但硬预算只有 3 次搜索、6 轮;轮次耗尽仍未给结论时,走同一条「无工具强制收尾」路径。

4. **证据纪律写进提示词 + 服务端双重兜底**,不纯靠模型自觉:
   - `searches[]` 由服务端按真实工具执行记录生成,模型无法虚报「我搜过」;
   - search 证据的 `url` 必须命中工具真实返回过的 URL 集合(knownUrls),编造/张冠李戴一律剥离;
   - evidence 非枚举值归一为 `market_pool`;旧字符串形态的 hit/gaps 也能兜底解析;
   - 搜索接口失败**占用**预算(防止换词重试把配额翻倍)但不进 `searches[]`(没有真实结果不算取证记录)。
   - 取舍记录:模型标了 `search` 但 url 无法与工具结果匹配时,保留 search 标签、剥离链接(标签反映「结论部分依赖补搜」这一事实,而 `searches[]` 可查实际补搜词),不武断改判为其他证据源。

5. **extracted 由服务端用段 1 结果直接回填**,不要求模型在结论里重复简历字段:减少输出体积与一次 JSON 出错面,也保证四区块里「照片识别」内容与视觉段严格一致。

6. **段 1 提取契约在原四键上追加 `degreeYear`(届别)与可选 `intent`(实习意向)**。任务书明确「届别/实习意向如图中写了就提」,原五键只有届别的位置,intent 为纯追加可选字段,旧消费方不受影响。

7. **前端过程状态全部来自服务端真实事件**:脉冲点 +「提取简历中 → 分析中(岗位池取证,必要时才补搜)→ 补搜 N 次」;不搜索时完成区显示「判断轮补搜 0 次(岗位池证据已足够,未花搜索配额)」,并展示 `stages` 两段实测毫秒数(文章实测数据直接取此)。证据标签配色沿用主题语义:📷图=紫(思考/模型读图)、📊岗位池=青(信号)、🔍搜索=琥珀(中),search 标签整体是可点链接。

8. **红线保持**:图片只在内存拼进视觉请求,不落盘、不写日志;无新 npm 依赖;TS strict;240s 总超时(请求断开与超时信号合并,同 radar 的 anySignal)。
