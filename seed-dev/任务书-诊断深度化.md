# 任务书：简历诊断深度化（视觉驱动的 Agent 循环）

## 背景

JobRadar（F:\——文章撰写——\火山\jobradar，Next.js 16 App Router + TS strict）的简历诊断目前是**单次视觉调用**。本次升级为三段式：**视觉提取 → 带搜索工具的判断轮 → 带证据标签的结论**，让视觉结果驱动工具决策，并让每条结论挂上证据来源。

先读 jobradar/AGENTS.md（该 Next.js 版本与训练数据可能有差异，必要时查 node_modules/next/dist/docs/）。

## 目标设计

`POST /api/diagnose` 升级为三段：

**段 1 · 视觉提取**：chatVision 读简历图 → `{skills, education, years, projects, degreeYear}`（届别/实习意向如图中写了就提）。沿用现有「照片模糊/字段缺失如实标未识别，禁止猜测补全」纪律。

**段 2 · 判断轮（核心）**：chatCompletion + 工具 `search_market`（包装 doubaoSearch，**预算 3 次**）。输入 = 段 1 提取结果 + slimJobs（现有瘦身逻辑保留）。系统提示词写明证据纪律：
- 岗位池（slimJobs）证据足够时**禁止搜索**（省配额，这也是被测行为：该取证才取证）
- 只有池子不足以支撑某条结论（如简历技术栈在池里没有对应行情）才补搜
- 每条结论必须标 `evidence: "resume" | "market_pool" | "search"`；标 search 的附来源 url

**段 3 · 结论 JSON**：外层保持 `{extracted, hit, gaps, target, conclusion}` **向后兼容**，扩展：
- `hit[]`、`gaps[]`、`target` 各带 `evidence`（search 的附 url）
- 新增 `searches: [{query, url?}]`——实际发生的搜索记录；空数组 = 判断轮没搜（这本身是有效结果）
- 新增 `stages: {extractMs, agentMs}`——各段耗时毫秒数（文章要写实测数据）

## 工程要求

- **失败重试**：段 1 或段 3 的 JSON 解析失败 → 自动整体重试 1 次；两次都失败才 502（修「模型偶发在 JSON 里插自言自语」的旧问题）。502 报文里保留失败原文片段（现有行为）。
- 总超时 240s；图片**依然严禁落盘/写日志**（沿用现有红线）。
- **不加新 npm 依赖**；TS strict；**不动** `/api/radar` 主流程、`lib/config.ts` 预算、RadarMap/JobMap 地图组件。
- **前端诊断区**：过程状态行（「提取简历中 → 分析中（可含『补搜 N 次』）→ 完成」）+ 四区块各条目的证据标签（📷图 / 📊岗位池 / 🔍搜索），风格融入现有面板。
- **不得破坏 ui-test.mjs 锚点**：配置页按钮文案精确等于「AI/算法/前端/全栈/测试/清空/杭州」、选中 chip 类名含 `border-cyan`、报告页判定词「技能要求词频」、运行页判定词「Agent 正在调研中」、岗位卡片用 `<article>`、📍/「必须:」/高/中/低可信文案。诊断区自身无锚点，可自由设计。
